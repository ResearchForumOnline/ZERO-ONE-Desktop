## 1. Proposed licence scope

Subject to final approved terms and applicable law, the proposed licence would grant one individual user a limited, non-exclusive, non-transferable right to install and use one approved ZERO ONE release on that user's compatible devices for personal or internal business purposes. The software would be licensed, not sold. No right would be granted to redistribute, sublicense, rent, host for third parties, or remove proprietary notices.

Any restriction on reverse engineering, decompilation, interoperability work, security research, backup copies, or error correction must preserve every right that applicable law does not permit the licensor to exclude.

## 2. Connected services and accounts

ZERO ONE provides a desktop boundary for separately operated or separately authenticated services, including ZMail, ZeroThink, OpenZero, and CallChat. A ZERO ONE licence would not create an account, subscription, service entitlement, content right, availability commitment, or licence to any third-party or connected service. Users remain responsible for satisfying each service's lawful account and usage terms.

## 3. Security and ZSEC limits

ZERO ONE and the ZSEC Shield preview would be supplied as software tools, not as guaranteed security, antivirus certification, real-time protection, incident response, or a promise to detect, prevent, remove, or recover from every threat. The preview scans only a folder the user explicitly selects and may produce incomplete, false-positive, or false-negative results. Users should preserve backups, apply supported operating-system updates, use suitable layered security, and review evidence before taking action.

## 4. AI-output limits

OpenZero model output may be inaccurate, incomplete, unsafe, outdated, or unsuitable for a user's intended purpose. ZERO ONE would not guarantee AI output or make decisions for the user. Users must review output before relying on it or using it in communications, professional work, security actions, or decisions affecting people. The final product still requires approved AI safety, moderation, governance, abuse-handling, and incident-response controls; these draft terms are not a substitute for those controls.

## 5. User responsibilities

Proposed user responsibilities include protecting account credentials and devices, maintaining appropriate backups, using only authorised data and systems, complying with applicable law and connected-service terms, checking AI and security results before acting, and not using the software to harm others or gain unauthorised access.
